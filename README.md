# Sustainable Edge Quality Intelligence

Research code, data and manuscript for **"Measured Edge-Inference Energy Versus Quality-Driven Carbon, Material, and Workload Effects of AI Defect Inspection in Manufacturing"**.

The study compares six inspection regimes for a functional unit of 1,000 parts in three manufacturing scenarios:

| Regime | Description |
|---|---|
| `N0_NoInspection` | no inspection; every defect escapes |
| `L0_Manual` | 100% manual end-of-line visual inspection |
| `B0`–`B3` | continuous edge-AI inspection (detect-and-divert) under the four alert policies measured in the companion alert-policy study (Paper A): single-frame threshold, smoothing, smoothing + k-of-N, full policy with incident latch |

It accounts for unrecovered material, recycling burden, rework / review / edge electricity, amortised edge-hardware carbon, field escapes and operator hours. Edge GPU power is **measured**; the alert policies' false-alert rates, alerts per defect, glare alerts and delays are **imported with their confidence intervals** from a pinned Paper A revision; everything else comes from a single parameter ledger with explicit provenance classes.

## Key results (central values; all numbers are regenerated by the pipeline)

* The PatchCore-style pipeline draws ~10 W on an RTX 4050 Laptop GPU at 30 FPS (~0.28 J per frame above idle). Thresholding, the temporal policy and event logging add no measurable power.
* The edge cell (electricity + amortised hardware) is ≤ ~1% of the full policy's carbon footprint and < 1% of its benefit over manual inspection.
* Edge AI beats manual inspection in every Monte Carlo draw. The benefit is driven by avoided field escapes and material, not by compute. Break-even defect prevalence against no inspection is in the ppm range.
* Alert policy matters more than compute: single-frame thresholding would need tens to hundreds of reviewers; the full policy (incident latch) saves operator time, electricity and carbon relative to it, unless persistence loses more recall than a break-even margin of about one percentage point for high-value parts.

See `paper/main.tex` and `results/paper_b_generated_metrics.tex` for the exact figures.

## Repository layout

```
configs/                 regime structure (policies.yaml), scenario class mix, SQI weight profiles
data/raw/source_registry.csv   single source of truth for every numerical parameter (validated schema)
data/raw/energy_measurements/  raw GPU power traces and per-window records of each benchmark run
data/raw/paper_a_exports/      provenance-tracked snapshot of the Paper A measurements (pinned commit, blob hashes)
src/                     model (quality, sustainability, pipeline), experiments, registry validation
scripts/01-10            pipeline steps (see below)
results/                 generated outputs: processed data, figures, tables, LaTeX macros
paper/                   manuscript; figures/, tables/ and the macro file are copies of results/
tests/                   unit, invariant, provenance and reproducibility tests
```

## Reproduce

```bash
python -m pip install -r requirements-lock.txt && python -m pip install -e . --no-deps
bash scripts/reproduce_all.sh            # analysis from the committed measurements (no GPU needed)
bash scripts/reproduce_all.sh --measure  # also re-measure GPU power (NVIDIA GPU + NVML; pip install -e .[bench])
```

| Step | Script | Output |
|---|---|---|
| 01 | `01_import_upstream.py` (optional) | refresh the Paper A snapshot from a local checkout (`--ref COMMIT`, `--out PATH`, `--update-registry`) |
| 02 | `02_validate_sources.py` | registry schema + consistency with measurement and Paper A snapshot |
| 03 | `03_measure_energy.py` (GPU, optional) | `results/raw/energy_summary.json`, raw traces, measured registry rows; `--out DIR` re-measures without touching them |
| 04 | `04_run_scenarios.py` | `regime_outcomes.csv`, `comparisons.csv` |
| 05 | `05_run_sensitivity.py` | one-way (tornado) sensitivity on registry bounds |
| 06 | `06_run_monte_carlo.py` | 10,000-draw Monte Carlo, PRCC global sensitivity |
| 07 | `07_run_break_even.py` | break-even frontiers (explicit "none" when no sign change) |
| 08 | `08_generate_figures.py` | figures (PDF + PNG) |
| 09 | `09_generate_tables.py` | LaTeX tables (parameter ledger generated from the registry) |
| 10 | `10_generate_macros.py` | checks every qualitative claim in the paper, writes all quoted numbers as macros |
| — | `sync_paper_assets.py [--check]` | copy generated assets into `paper/` (never edits `main.tex`) |
| — | `verify_math_proofs.py` (needs `.[dev]`) | SymPy proofs of the Section III model, dimensional analysis, paper-vs-code equivalence, closed-form break-even checks, manuscript literals vs registry |
| — | `package_release.py` | clean LaTeX build + reproducible release zips in `dist/` |

All paths are repository-relative. CI regenerates every result from the committed inputs, fails on any drift, and compiles the manuscript.

## Provenance and limitations

Most parameters are scenario assumptions and are labelled as such in the ledger and in Table I of the paper. The measurement covers the GPU only; host, camera and lighting power enter through the `host_power` assumption. The benchmark used a GPU that also drives the host desktop under WSL2. On that setup the NVML cumulative energy counter was inconsistent with the power sensor, so power samples are integrated instead. The reported statistics are medians with min–max bounds. See the paper's threats-to-validity section.
